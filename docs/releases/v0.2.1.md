# v0.2.1 — 装得上、装完能自证

这一版**没有改运行逻辑**，只解决"别人装上之后能不能用、能不能自己确认"。

## 安装（给别人装）

在 DSH 的「设置 → 插件」里用安装入口填这个**安装说明符**：

```
github:BlankTasftu/dsh-delivery-library
```

等价的命令行写法（桌面端不自带 `dsh` CLI，所以多数人走设置页）：

```powershell
dsh plugin --profile <你的 profile> add github:BlankTasftu/dsh-delivery-library
```

装好后页签从 `对话 | 轨迹` 变成 `对话 | 轨迹 | 交付文件`。宿主会把新的启动图推给
已打开的页面，一般不用手动刷新；没出现就按一次 F5。

## 装完自证（零依赖）

包内自带测试与排查工具，不需要安装任何东西：

```powershell
node --test "test/*.test.mjs"          # 期望 60/60
node tools/check-host-resolution.mjs   # 从 profile 出发能否解析到 browser bundle
node tools/check-boot-graph.mjs        # 插件在不在启动图、在哪个批次、批次能否投递
```

## 这一版修了什么

- **`test/` 与 `tools/` 现在随包交付**。此前它们被 `files` 过滤掉，而 package.json 里
  却带着 `test` 脚本 —— 装到别人机器上以后 `pnpm test` 会得到 `tests 0` 且退出码非 0，
  等于"装完无法自证"。
- **探针缓存搬出工作区**：`tools/check-profile-patch.mjs` 抽 js-yaml 的缓存从
  工作区 `.cache/` 改到系统临时目录，包被安装在 `node_modules` 里时不再往包目录写文件。
- **README 安装章节重写**：把"给别人装"放到最前，附自检命令与三个只读探针。

## 实测（都在这台机器上真跑过）

| 验证 | 结果 |
| --- | --- |
| 远端与本地一致性 | `main` 与 `origin/main` 同一提交，工作区 0 项未提交改动 |
| 干净克隆自洽性 | `git clone` → `node --test` → **60/60**（无需安装任何依赖） |
| 干净实装 | `pnpm add github:BlankTasftu/dsh-delivery-library` → **4.9s**，装到 **0.2.1**（24 个文件） |
| 装进去的必需件 | `lib/index.js`、`lib/client.js`、`cordis.patch.yml`、`package.json` 齐全；`test/`、`tools/` 也在 |
| **装完自证** | 在**装好的包目录里**跑 `node --test "test/*.test.mjs"` → **60/60**，退出码 0 |
| DSH 宿主的解析链 | 以安装目录为 profile 验证：`dsh.client` → `exports["./client"]` → `lib/client.js` → bundle patch → 宿主入口，**全部可解析** |
| 无安装脚本 | 包内无 `preinstall`/`postinstall`/`prepare`，无第三方依赖，无 `bin` |

## 安装边界（重申）

这是个**纯插件**：宿主半侧是空实现（零 `import`／零 `require`），浏览器半侧只
`require('react')` —— 不联网、不写任何存储、不碰文件，运行时只注入一份带标记的
`<style>`、注册一个视图格子、注册两份词典。`test/isolation.test.mjs` 用 10 条静态
断言把这条边界钉住。
